GuardianBridge v1.4 Help

GuardianBridge uses SQLite as the single source of truth for subscribers, node status, chat, SOS events, queues, and scheduled jobs.

Core Services

  • meshtastic_dispatcher.py: main radio dispatcher and queue worker.
  • email_processor.py: processes inbound/outbound email via SQLite-backed queues.
  • weather_fetcher.py: fetches weather/alert data for broadcasts and UI.

Web Panels

  • map.php: full admin panel (settings, users, actions, broadcast scheduling, SOS operations).
  • mop.php: operator panel optimized for live monitoring and chat response.

Operational Notes

  • Command actions from web/email are queued in SQLite command_jobs.
  • Dead-letter rows are managed in SQLite command_dead_letters.
  • After changing .env values, restart the dispatcher service.

Primary Runtime Paths

  • /opt/GuardianBridge/data/guardianbridge.db
  • /opt/GuardianBridge/data/dispatcher_status.json
  • /opt/GuardianBridge/data/weather_current.json
  • /opt/GuardianBridge/data/weather_forecast.json
  • /opt/GuardianBridge/data/nws_alerts.json

For full documentation, see /opt/GuardianBridge/README.md and /opt/GuardianBridge/Docs/ARCHITECTURE.md.
